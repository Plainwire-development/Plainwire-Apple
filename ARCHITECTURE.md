# Architecture

Plainwire defaults to `https://plainwi.re` and can connect to a self-hosted installation selected in the server-host picker. `AppModel` owns the active configuration and state shown by SwiftUI. `PlainwireAPIClient` handles HTTP requests, and `PlainwireRealtimeClient` handles the WebSocket connection. The two clients are Swift actors.

Switching hosts ends calls, signs out, invalidates old HTTP work, stops realtime, resets WebKit, and clears private images, notifications, and rooms before creating clients for the new configuration. Domain cookies are removed so installations on different ports cannot share authentication. Draft and device mute keys include the full deployment URL and user ID; switching saves drafts while explicit sign-out deletes that account's drafts. Session generations reject stale restore/login/bootstrap results. The selected host and recent addresses persist in UserDefaults; credentials are never part of those addresses. HTTPS is required for public hosts; local HTTP is permitted for loopback, private IPv4, and `.local` names.

## Sessions and sync

Login sets a `pw_session` cookie. The app restores it with `GET /api/me` and sends the session's CSRF token on changes. Passwords are not stored by the app.

Secondary tools use an ephemeral `WKWebView` presented as a sheet. Before loading the web client, the app copies the active session cookie into WebKit's cookie store. Web sign-out removes the native session too. Closing the sheet refreshes the account and server state. The web store does not persist between app sessions. A retained `WorkspaceController` owns the WebKit view, dialogs, and downloads so subsequent tool presentations preserve their state. Sign-out cancels and clears it.

`GET /api/sync` refreshes conversations, servers, and friends. The server supplies the cursor for later syncs. Opening a room fetches its messages; the earlier-messages button loads older pages while preserving the first visible row. Reconnection refreshes the live tail and fills gaps with paginated requests. Context jumps use the bounded message-context endpoint and offer a return to the latest messages. The app keeps up to 12 recent rooms in memory.

Realtime events update messages, reactions, typing, and presence. After a disconnect, the socket reconnects, restores subscriptions, and syncs with the server. The server remains the source of truth.

The native model consumes connection states and events through one ordered stream. Presence uses only the current socket's snapshots and updates; saved profile status is never evidence that someone is connected. Sparse snapshots confirm omitted watched users are offline; new watches and disconnected sockets remain unknown. Profile sheets add temporary watches, and server resync restores watches/subscriptions. Hello and pong deadlines detect silent connections. Detail requests are coalesced separately so they cannot delay presence or typing events.

## Forums

`ForumStore` owns native forum navigation, memberships, search results, posting state, and up to six recent discussion details. It shares `AppModel`'s API actor and authenticated session. The implementation follows the backend in `~/Plainwire` (reference commit `b3dd2e1ce8f88c705a73eae16455629dc9d22b40`), using `/api/forums`, `/api/threads`, `/api/forum/:id/*`, and `/api/thread/:id/*`. It reads and writes the website's existing data; it does not keep a separate forum database or require backend changes. Server-supplied permissions govern editing, deleting, and moderation, with omitted flags defaulting to denied. Editors preserve `raw_body` and validate the backend's UTF-8 byte limits.

Visible and joined forums subscribe through the existing realtime connection. Thread/reply events trigger a debounced authoritative refresh; deletion events remove content immediately and leave tombstones so older requests cannot restore it. Search revisions prevent a slow result from replacing a newer query. While Forums is visible and the app is active, a 30-second refresh also picks up votes and membership/count changes that the backend does not broadcast. Navigation and caches reset on sign-out or host switching; the old store is invalidated before a fresh one is created. New-discussion and reply drafts use the existing host/account draft namespace. Incoming replies preserve the reading position; a successful native reply scrolls to that reply.

Community cards, discussion lists, post bodies, and editors use native SwiftUI navigation and scrolling with bounded reading widths. Shared semantic canvas/panel colors follow system appearance; continuous rounded shapes and increased-contrast borders keep surfaces consistent across the app. See Apple's [layout](https://developer.apple.com/design/human-interface-guidelines/layout), [tab bar](https://developer.apple.com/design/human-interface-guidelines/tab-bars), and [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) guidance.

## Chat and media

Messages use `LazyVStack`. Drafts are keyed by room, saved per account with debounced writes, restored after relaunch, and removed on sign-out. Sends and uploads capture their original room. Session generations discard old asynchronous results; bounded deletion records keep overlapping fetches from restoring removed messages. Parsed Markdown, attachments, and timestamps are reused until message content changes. New messages scroll into view only when the reader is near the bottom. Loading older messages keeps the previous first row in place.

Uploads stream from file URLs. Attachment Markdown is separated from visible message text. `||attachment||` hides that attachment until the reader reveals it. Images and avatars share a 96 MiB cache budget: 72 MiB for decoded assets and 24 MiB for downloaded sources. Transfers coalesce by URL across display sizes, while size buckets reuse utility-task ImageIO thumbnails and GIF decoders. Warm images are available synchronously during layout. GIF/APNG sources retain frame timing and decode frames on demand into a per-image cache bounded by 12 frames and 8 MiB; small avatars reserve only their downsampled frame cost. Native AppKit/UIKit layers display frames without SwiftUI row updates. Playback cancels when detached or hidden and pauses with app inactivity, autoplay off, or Reduce Motion. Cache generations clear both source and decoded caches, remove already displayed private images, and reject old transfers after sign-out or host switching. Attachment extraction and code/spoiler parsing live in the portable core and have regression tests. Authenticated downloads are staged in a session-specific temporary folder for Quick Look and removed on sign-out. Video playback starts when tapped.

AVKit platform views provide video controls directly. A shared playback owner cancels preparation, removes observers, and releases media when rows disappear. Voice-note progress updates run only during playback. Images use delegate-owned disk downloads with transfer and dimension limits before decoding. API responses are not cached to disk, and API redirects must remain on the configured origin.

## Native calling

`CallController` owns a single call or voice-channel room, permissions, participant state, native audio/video tracks, camera capture, relay refresh, and teardown. `NativeCallPeer` owns one native WebRTC transport per remote participant. The app pins the WebRTC XCFramework package to 154.0.0. The existing authenticated Swift API client reads `GET /api/rtc-config`; the existing realtime socket sends the server’s `call_*` and `voice_*` commands. No web assets, JavaScript, WebKit media engine, separate web session, or backend changes are used for calls.

The higher user ID offers, matching the existing signaling protocol. Per-peer task queues serialize SDP and ICE; bounded candidate buffers hold ICE until its description is applied. Worker-thread delegates explicitly hop to MainActor. Room identity and lifecycle generations reject stale events and completions. Reconnection rebuilds transports and rejoins the current room; mute/deafen state is republished after joining. Sign-out, revoked access, superseded sessions, and hang-up stop capture and close transports. The floating native call panel overlays root navigation and can be dragged, resized, reset, or minimized without stopping media. Shared layout bounds keep it reachable after window resizing and rotation. Native AppKit/UIKit pointer handlers measure window-coordinate movement from a fixed interaction anchor, avoiding SwiftUI GestureState executor callbacks. Account-wide call_presence is tracked independently of locally owned media, so website conversation calls can be displayed and explicitly transferred with call_join. The Mac sandbox allows incoming and outgoing UDP for native ICE/media, following [Apple’s network entitlement guidance](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.network.server). The app includes a local-network usage description for direct peer connections.

## Platforms and notifications

iPhone uses tabs; iPad and Mac use split views. The app targets iOS 18 and macOS 15. Newer SwiftUI effects are guarded by OS availability checks.

On Mac, `MacRootView` uses native `HSplitView` panes within a viewport that follows the actual window size. The sidebar keeps its identity and account footer outside its scrolling List; the conversation pane keeps its search and filters outside its List. Scrollable children explicitly allow a zero minimum height so their document size cannot become the window's minimum content height. This replaces the Mac three-column navigation layout that let native list viewports exceed the window and center their first rows outside it. The iPad navigation split view and iPhone tabs retain their platform navigation. See Apple's [split view](https://developer.apple.com/documentation/swiftui/hsplitview) and [layout guidance](https://developer.apple.com/design/human-interface-guidelines/layout).

Local notifications are sent for incoming messages while the app is running. Permission is requested from Settings. iOS stops the WebSocket in the background and syncs on return. Background iPhone push needs an APNs registration and delivery service. Native calls end before iOS suspends the realtime connection. Continuing calls in the background and receiving calls while suspended require background audio, CallKit, and push integration.

Mac Settings uses native TabView preferences and grouped forms; the sidebar uses system List selection. Interface animation and media autoplay honor accessibility settings. GIF search uses `GET /api/gifs/search` and best-effort `POST /api/gifs/share` on the selected host. Search requests are debounced and reject stale results; insertion sanitizes Markdown, preserves the original room, and keeps the GIF in the draft until the user sends it. Device-local conversation muting suppresses notifications without sending an unsupported mutation to the reference backend. Command-Return sends on every composer preference; plain Return can be configured to send or add a line.

Mac sheets use fitted presentation sizing with minimum and ideal dimensions, allowing users to resize them. Settings forms use the native grouped form's scrolling rather than nesting vertical scroll views. The sidebar uses a semantic background behind its list and fixed account controls, and avatars sit outside native menu labels to preserve their clipping and animation. The separate Settings scene follows the same account appearance preference as the main window. See Apple's guidance on [scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views), [materials](https://developer.apple.com/design/human-interface-guidelines/materials), and [fitted sheet sizing](https://developer.apple.com/documentation/swiftui/presentationsizing/fitted).
